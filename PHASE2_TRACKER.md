# Phase 2 Feature Tracker

This file is the **linking bridge** between the current app (Phase 1) and Phase 2 (React + Vite).

## How it works

- **Current App session:** When a new feature is added to `bangle_v19.html`, log it below under "Pending for Phase 2"
- **Phase 2 session:** At the start of each session, read this file. Implement all "Pending" items, then mark them "Done"

## Known gaps — confirmed missing or unverified, not yet built

> Found during the 2026-08-07/08 audit. Listed so a future session doesn't have to rediscover them.

- **Library page — bulk operations deliberately deferred.** The core browse/upload/organize workflow is built (see #27 above): segment → folder → photo grid, upload, delete, rename/delete folder. The picker integration (attach a library photo to a design row) is also built now — see #31 above. NOT ported: bulk multi-select (move/copy/delete many at once), "Import Folder" (bulk local folder import with skip-patterns for Picasa/thumbs.db junk), "Sync from R2" (scan the bucket directly), the rclone guide, and the separate "📸 Upload & Assign to Orders" photo-recovery tool.
- **Designs page** — structurally sound (groups by code like Phase 1's Design view, edits real `design.stages[]` fields), but visually different (expandable rows vs Phase 1's horizontal stage-pill flow) and missing per-item export/print buttons.
- **Inventory — intentionally removed from Phase 2, not a gap.** See item #19 above. If the business ever revives production-stage tracking in Phase 1 (i.e. builds a live way to set `design.stages[].status/qty` again), this decision should be revisited — until then there's nothing live to sync from.
- **Analytics — dead-code KPI quirk resolved by deliberate divergence (see #22 above).** Phase 1's real order-level `orderAlert()` only returns `'done'`/`'pending'`; `renderAnalytics()`'s KPI card still calls it expecting 4 states, so `lateOrds`/`warnOrds` are always 0 in the live Phase 1 app (dead code from before that function was simplified). Phase 2 now shows a real "Pending" count instead of a permanently-0 "Overdue" metric — different from what Phase 1 displays, but the live data underneath is real, and this was a deliberate choice, documented rather than silent.
- **Users page (Masters → Users in Phase 1) is not actually a standalone top-level nav item in Phase 1** — it's a tab inside the "📋 Masters" page (which doesn't exist in Phase 2 at all — see Masters gap above). Phase 2 exposes it as its own `/users` route instead. Functionally equivalent access control either way (owner-only for management, self-service for everyone else), just a different information architecture.
